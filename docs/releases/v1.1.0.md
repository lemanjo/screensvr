# screensvr v1.1.0

Curated online photo backgrounds and a simpler management interface for screensvr,
the self-hosted idle screen for smart-home tablets.

## Highlights

- **Wikimedia and NASA backgrounds:** choose landscapes, birds, flowers, or
  architecture from Wikimedia Commons, or nebulae, Earth from space, and planets
  from NASA's image library. No account or API key is needed.
- **Ready to choose:** Online backgrounds is automatically added and enabled on
  new installations and upgrades. Select an album under **Photo Hours → Data
  sources → Photos**. No album is selected or downloaded automatically.
- **Image credits included:** Photo Hours displays the title, creator/source, and
  license or usage-guidelines link for each online image. Attribution-capable
  custom faces can also use online albums.
- **Server-side image delivery:** bounded, memory-only caches, resized images,
  conservative credit/license filtering, and retry backoff. Tablets do not need
  to contact image providers directly.
- **Simpler management:** shorter labels, less repeated copy, cleaner sign-in and
  responsive layouts, and expandable setup and scheduling help. Existing face
  defaults, saved content, and privacy/security warnings are preserved.

## Install and requirements

Use `ghcr.io/lemanjo/screensvr:v1.1.0` with a persistent volume at `/data`.
The image becomes available only after the **Release container** workflow succeeds.
Published images support **Linux amd64 only**; ARM requires a local build.
Source installations require **Node.js 24 LTS**.

Follow the [quick start](https://github.com/lemanjo/screensvr/blob/v1.1.0/README.md#quick-start).
Fully Kiosk's screensaver feature requires **Fully PLUS**. Immich support requires
**3.4.1 or later within 3.x**. Integrations must be reachable from the server.
Online backgrounds require server-side internet access when used.

## Upgrade from v1.0.0

1. Stop screensvr and back up the **complete data directory**, including
   `screensvr.sqlite`, installed faces, and the matching `integration-key` if present.
   Protect the backup as sensitive data.
2. Change your image to `ghcr.io/lemanjo/screensvr:v1.1.0`, then run:

   ```sh
   docker compose pull screensvr
   docker compose up -d screensvr
   ```

3. Check `/api/health` for version `1.1.0`, sign in, and verify your displays,
   scenes, schedules, and integration connections.

Existing displays, links, settings, and photo selections are preserved. The
database schema remains at version 5. Online backgrounds is provisioned once;
disabling or removing it persists across restarts. Existing connections are not
duplicated, and the built-in connection does not consume a custom-integration slot.
No provider requests occur until an album is actively selected, previewed, or the
connection is explicitly tested.

For installations older than v1.0.0, also read the
[v1.0.0 upgrade notes](https://github.com/lemanjo/screensvr/releases/tag/v1.0.0).

**Rollback:** stop the new version, restore the complete pre-upgrade backup, and
run its matching application version. Do not run an older version against the
upgraded data directory or share a data directory between processes.

See [deployment, backups, and recovery](https://github.com/lemanjo/screensvr/blob/v1.1.0/docs/deployment.md).

## Privacy and known limits

- Online albums are changing third-party collections, **not a guarantee of
  family-safe content**. Preview selections before using a shared screen.
- Each curated album contains up to 48 eligible images and can be smaller or
  empty after filtering. Custom searches and arbitrary provider URLs are not supported.
- Online image credits cannot be disabled. Custom faces must explicitly support
  the [attribution contract](https://github.com/lemanjo/screensvr/blob/v1.1.0/docs/faces.md#online-image-attribution);
  existing mounted-folder and Immich inputs are unchanged.
- Provider outages can pause rotation. Caches are memory-only; this is not an
  offline download library. A loaded photo can remain visible, but restarting or
  reloading selected online albums requires internet access.
- Display links and read-only display APIs do not require login. Anyone who can
  reach them can read selected content, including the whole selected photo
  collection. Use a trusted LAN, VPN, or proxy access controls.
- Integration credentials stay on the server. Install only trusted face packages:
  they contain executable JavaScript.
- Fully Kiosk or the device controls idle activation, hardware brightness, and
  screen power. Night mode dims the page, not the backlight.
- Automated tests use fake services, mocked provider responses, and desktop
  browsers; they do not replace real-service or Fully Kiosk/Android device testing.
- The existing, development-only `picomatch 4.0.7` advisory acceptance expires
  **2026-12-17 00:00 UTC**. Production dependencies have no exceptions.
  See the [security policy](https://github.com/lemanjo/screensvr/blob/v1.1.0/SECURITY.md#temporary-development-tool-advisory-acceptance).
