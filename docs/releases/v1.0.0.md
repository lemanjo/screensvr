# screensvr v1.0.0

The first stable release of screensvr: a self-hosted, calmer idle screen for
smart-home tablets, designed for Fully Kiosk Browser and other modern browsers.
No screensvr cloud account or subscription is required.

## Highlights

- **Eight bundled faces:** Slow Hours, Soft Orbit, Color Drift, Color Drift Night,
  Stillroom, Photo Hours, Weather Hours, and Calendar Hours.
- **One place for every display:** independent face settings and timezones,
  permanent display links, live previews, and automatic updates to connected screens.
- **Scenes and weekly schedules:** save complete looks with their data sources,
  switch them in the display's timezone, and add a near-black night clock.
- **Photos:** use read-only local/NAS folders or owned/shared Immich albums, with
  slideshow, shuffle, fill/fit, and an optional clock.
- **Home Assistant:** display sensor readings, current weather, forecasts, and
  calendar appointments through server-side, read-only connectors.
- **iCalendar:** subscribe to read-only feeds with recurrence and timezone support.
  Calendar titles remain private unless explicitly published; busy-only is the default.
- **Custom faces:** install trusted ZIP packages without rebuilding, or build a face
  with HTML, CSS, JavaScript, and the documented SDK.
- **Deployment and security:** non-root container, encrypted integration credentials,
  immutable releases, container scanning, provenance, and an attested CycloneDX SBOM.
- **Face-file hardening:** descriptor-based manifest and asset reads, no-follow
  file opens, and an explicit directory containment check before removing a face.
- **Updated documentation:** quick start, Fully Kiosk setup, integrations, operations,
  face development, and a framework-free Paper example.

## Install and requirements

Use `ghcr.io/lemanjo/screensvr:v1.0.0` with a persistent volume at `/data`.
The image becomes available only after the **Release container** workflow succeeds.
Published images support **Linux amd64 only**; ARM requires a local build.
Source installations require **Node.js 24 LTS**.

Follow the [quick start](https://github.com/lemanjo/screensvr/blob/v1.0.0/README.md#quick-start).
Fully Kiosk's screensaver feature requires **Fully PLUS**. Immich support requires
**3.4.1 or later within 3.x**. Integrations must be reachable from the server.

## Upgrade from v0.1.0

1. Stop screensvr and back up the **complete data directory**, including
   `screensvr.sqlite`, installed faces, and the matching `integration-key` if present.
   Protect the backup as sensitive data.
2. Change your image to `ghcr.io/lemanjo/screensvr:v1.0.0`, then run:

   ```sh
   docker compose pull screensvr
   docker compose up -d screensvr
   ```

3. Check `/api/health` for version `1.0.0`, sign in, and verify your displays and
   integration connections.

Database migrations run automatically. Existing assignments and settings are
preserved in a default scene, with scheduling initially disabled. Legacy UUID
display links redirect to permanent, name-based addresses; old pairing fragments
and display cookies are no longer needed.

**Rollback:** stop the new version, restore the complete pre-upgrade backup, and
run its matching application version. Never run an older version against the
upgraded database or share a data directory between processes.

See [deployment, backups, and recovery](https://github.com/lemanjo/screensvr/blob/v1.0.0/docs/deployment.md).

## Privacy and known limits

- Display links and read-only display APIs do not require login. Anyone who can
  reach them can read selected content, including the whole selected photo
  collection and data a face hides. Use a trusted LAN, VPN, or proxy access controls.
- Integration credentials stay on the server. Only install face packages from
  trusted sources: they contain executable JavaScript.
- Fully Kiosk or the device controls idle activation, hardware brightness, and
  screen power. Night mode dims the page, not the backlight.
- Loaded faces can continue during an outage, but offline startup, reloads, and
  offline scene transitions are not supported.
- One installed version per face ID is supported. Automatic face updates,
  registry downloads, multi-user roles, and native kiosk control are not included.
- Automated tests use local fake services and desktop browsers; they do not
  replace real-service or Fully Kiosk/Android device testing.
- The existing, development-only `picomatch 4.0.7` advisory acceptance expires
  **2026-12-17 00:00 UTC**. Production dependencies have no exceptions.
  See the [security policy](https://github.com/lemanjo/screensvr/blob/v1.0.0/SECURITY.md#temporary-development-tool-advisory-acceptance).
